# JSBSim HIL 故障注入使用说明

## 1. 打开顺序

1. 运行修改后的 `MissionPlanner.exe`。
2. 按 `Ctrl+F` 打开“Mission Planner 开发工具”。
3. 点击“JSBSim HIL 环境”，启动 `hil_supervisor.py` 并等待 Ready。
4. 返回开发工具页，点击“JSBSim HIL 故障注入”。
5. 点击“连接测试”，状态显示“已连接”后即可配置故障。

两个窗口访问同一个 `http://127.0.0.1:8765/` 本机接口，不会抢占 COM6。

## 2. 故障通道

默认提供 8 个独立通道（编号 0～7）。每个通道包含：

- 故障使能；
- 故障类型和对象；
- 阶跃或渐变；
- 故障程度和副参数；
- 触发延迟、渐入、保持和恢复时间；
- 自动恢复开关。

多个通道可以同时工作，因此不需要预先写死复合故障组合。例如：

- 通道 0：推力损失 40%；
- 通道 1：升降舵舵效损失 30%；
- 通道 2：空速固定偏差 +5 m/s。

保持时间设为 0或取消“自动恢复”时，故障持续到手动清除。点击“全部故障恢复”会立即清除所有通道。

## 3. 支持的故障

| 类型 | 对象 | `level` | `secondary` |
|---|---|---:|---:|
| 推力损失 | 动力系统 | 损失比例 0～1 | 未使用 |
| 舵效下降 | 副翼/升降舵/方向舵 | 损失比例 0～1 | 未使用 |
| 舵面卡死 | 副翼/升降舵/方向舵 | 卡死角度（°） | 未使用 |
| 传感器噪声 | 空速/气压高度 | 高斯噪声 σ | 未使用 |
| 传感器漂移 | 空速/气压高度 | 每秒漂移速率 | 最大漂移量 |
| 传感器固定偏差 | 空速/气压高度 | 固定偏差 | 未使用 |
| 传感器冻结/失效 | 空速/气压高度 | 未使用 | 未使用 |

空速单位为 m/s，高度单位为 m。

## 4. 注入位置

执行机构故障采用以下链路：

```text
飞控原始 SERVO PWM
  → 正常执行机构归一化输出
  → 故障注入层
  → JSBSim 实际舵面/推进输入
```

原始 PWM 始终保留在 `servo_pwm_us` 中。故障控制器另外记录 `normal` 和 `actual`，不会把缩放后的数值回写飞控。

传感器故障采用以下链路：

```text
JSBSim 真值
  → 故障注入层
  → JBS1 空速/高度/静压/动压测量
  → 飞控
```

空速故障通过动态压力换算进入 JBS1；高度故障同时改变高度测量和与之对应的静压，但不修改 JSBSim 内部真实位置。

## 5. 本机 API

- `GET /api/v1/vehicles/{sysid}/faults`：读取通道和真实/故障后数据；
- `PUT /api/v1/vehicles/{sysid}/faults/{slot}`：配置或更新通道；
- `POST /api/v1/vehicles/{sysid}/faults/{slot}/clear`：清除一个通道；
- `POST /api/v1/vehicles/{sysid}/faults/reset`：清除所有通道。

HTTP 线程只提交命令。命令由 400 Hz 物理线程应用，避免 HTTP、串口和 JSBSim 同时修改状态。

## 6. 记录文件

每次运行目录新增：

- `fault_events.jsonl`：命令、故障阶段变化、触发和解除时刻；
- `fault_status.csv`：通道、正常/实际执行机构量、传感器真值/测量值和有效状态。

## 7. 当前协议限制

现有 JBS1 116 字节协议没有单独的空速和高度 `valid_flag` 字段。因此冻结故障会保持最后一个有效测量值，并在本机 API/日志中记录 `valid=false`；飞控侧只能通过冻结/超时健康检查识别失效。若需要飞控立即读取显式失效标志，必须同时扩展 JBS1 payload 和 `AP_ExternalAHRS_JSBSim` 固件解析器。
