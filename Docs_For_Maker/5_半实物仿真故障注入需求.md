# 半实物仿真故障注入需求

## 1. 总体要求

为验证故障诊断、故障辨识及系统容错功能在半实物仿真条件下的有效性，应在半实物仿真平台中设置独立的故障注入模块，实现动力系统、舵面执行机构及传感器等典型故障的可控注入。

故障注入模块应满足以下要求：

1. 故障注入参数应至少包括**故障使能标志、故障类型、故障位置、故障模式、故障程度、触发时刻、渐变时间、持续时间及恢复方式**等信息。
2. 所有故障程度均采用**外部可配置参数**设置，需求阶段不固定具体故障程度。仿真过程中可根据试验目的直接修改故障程度，无需修改控制算法或底层模型程序。
3. 支持单故障和复合故障注入。不同故障通道应相互独立，可同时使能多个故障，并分别设置各自的故障位置、故障程度、故障发生时刻及变化规律。
4. 应设置明确的故障注入接口和使能标志。单个故障通道至少包含：
   - `fault_enable`：故障使能标志，0表示正常，1表示故障激活；
   - `fault_type`：故障类型标志；
   - `fault_target`：故障对象/故障位置标志；
   - `fault_profile`：故障变化形式，包括阶跃、渐变等；
   - `fault_level`：故障程度；
   - `fault_start`：故障开始时刻；
   - `fault_ramp`：渐变时间；
   - `fault_duration`：故障持续时间；
   - `fault_clear`：故障解除或恢复控制标志。
5. 复合故障情况下，每个故障应具有独立的一组参数和使能标志，不采用单一总故障标志区分多个故障。
6. **损失类故障不得通过修改飞控系统输出的控制指令实现。**飞控系统输出的油门指令、升降舵指令、方向舵指令和副翼指令均应保持正常，以保证能够真实反映故障发生后控制器的响应过程。
7. 推力损失应注入动力系统底层模型或实际推力输出环节；舵效损失应注入舵机/执行机构模型、实际舵面偏角或飞机动力学模型中的舵面作用环节。故障诊断算法能够同时获取正常控制指令和发生故障后的实际响应。
8. 传感器类故障应注入传感器输出或数据采集接口，不修改飞机真实状态量。应同时保留真实状态量和故障后的测量量，便于后续故障诊断结果分析和算法验证。

## 3. 损失类故障注入原则

为保证半实物仿真结果能够真实反映执行机构或动力系统性能退化后的闭环响应，推力损失和舵效下降等损失类故障统一采用**物理作用端注入**方式。

### 3.1 推力损失

飞控输出的油门指令 `u_T_cmd` 保持不变。

正常情况下：

```text
u_T_cmd → 动力系统模型 → T_normal
```

发生推力损失后：

```text
u_T_cmd → 动力系统模型 → 故障注入模块 → T_fault
```

其中可采用：

```text
T_fault = (1 - λ_T) T_normal
```

因此，飞控系统仍然能够观察到由于实际推力不足造成的速度、高度及姿态变化，并产生相应的闭环补偿控制。

不得直接采用：

```text
u_T_fault = (1 - λ_T) u_T_cmd
```

作为半实物仿真中的主要推力损失注入方式。

### 3.2 舵效下降

飞控输出的舵面指令 `δ_cmd` 保持不变。

故障应作用于舵机输出、实际舵面偏角或动力学模型中的舵面控制效应，可根据半实物平台实际模型结构选择具体注入位置。

例如采用实际舵偏损失方式时：

```text
δ_fault = (1 - λ_δ) δ_normal
```

其中 `δ_normal` 为正常执行机构模型输出，而不是飞控系统输出的原始舵面指令。

如果底层六自由度模型能够直接修改舵面气动力/力矩作用，也可在动力学模型中直接降低相应舵面的控制效能。

无论采用何种实现方式，均应保证：

```text
δ_cmd、δ_actual 和故障后的飞机状态响应
```

可以分别记录。

## 4. 复合故障注入要求

半实物仿真平台不应仅预设若干固定的“双故障组合”，而应采用多故障通道并行方式实现复合故障。

建议至少设置若干独立的 `Fault Channel`，每个通道均具有：

```text
Enable + Type + Target + Profile + Level + StartTime + RampTime + Duration
```

因此可以通过分别配置各故障通道实现：

- 推力损失 + 升降舵舵效下降；
- 推力损失 + 方向舵舵效下降；
- 推力损失 + 副翼舵效下降；
- 升降舵 + 方向舵舵效下降；
- 升降舵 + 副翼舵效下降；
- 方向舵 + 副翼舵效下降；
- 多个执行机构同时故障；
- 执行机构故障 + 传感器故障；
- 多传感器同时故障。

各故障通道的发生时刻应能够独立设置，因此既支持**同步复合故障**，也支持**异步复合故障**。

## 5. 数据记录要求

半实物仿真过程中至少同步记录以下数据：

1. 各通道原始控制指令；
2. 各执行机构正常模型输出；
3. 故障注入后的实际舵面偏角及实际推力；
4. 故障类型、故障位置、故障使能标志和实际故障程度；
5. 各故障的触发时刻、达到目标程度时刻和解除时刻；
6. 飞机真实状态量；
7. 传感器原始真实值及故障注入后的测量值；
8. 各传感器数据有效标志；
9. 复合故障情况下每个故障通道的独立状态。

通过上述数据，应能够明确区分：

- 控制系统希望执行的控制量；
- 执行机构实际实现的控制量；
- 飞机最终产生的状态响应。

以满足后续故障检测、故障隔离、故障程度估计及剩余能力评估的验证需求。
